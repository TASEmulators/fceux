## Why

Win32 前端仍有不少用户可见英文直接写在 C/C++ 源码中，不会随 `res.rc` 的简体中文资源切换，导致菜单和静态对话框已汉化但消息框、动态标题、状态文本及文件选择器仍显示英文。需要对 Win32 源码文案做一次可审计的专项补全，消除混合语言界面，同时以大众通行用法为准，避免误翻运行数据和 TAS/NES 专有名词。

## What Changes

- 扫描 `src/drivers/win` 下 C/C++ 源码中传给 Win32 UI API 的字符串字面量及由源码拼接生成的可见文案，建立逐项分类清单。
- 将应翻译的消息框、动态窗口/控件标题、状态提示、工具提示、文件对话框标题与筛选器迁移到现有双语字符串资源和宽字符本地化辅助层。
- 对设备名、文件名、路径、地址、寄存器、数值、日志/反汇编内容和配置键等运行数据保持原样。
- 采用保守的术语判定规则：产品和项目名称、工具/模块名称、文件格式、协议、缩写及独有 TAS/NES 术语默认保留原文；只翻译普通界面操作和已有单一、稳定、大众通行中文译法的概念；无法确认或社区用法存在分歧时保留英文，不做逐字硬译或自创中文名称。
- 为每个术语记录类别、处理结论和依据，使 FCEUX、NES、TAS、ROM、RAM、CPU、PPU、APU、Lua、FM2/FM3 等保留项以及允许翻译的通用词都可审查、可自动验证。
- 对不能或不应翻译的源码字符串记录保留理由，并增加自动化检查，防止新的 Win32 用户可见英文字符串绕过本地化登记。
- 使用 Visual Studio 2022 `v143` 构建并验证 `Release|Win32`，同时在英文和简体中文模式下检查动态文案、格式参数、Unicode 路径和英文回退。
- 本变更只影响 Win32 前端，不修改 `res.rc` 中已完成的静态翻译，不涉及 Qt/SDL 前端、模拟核心、文件格式或命令行输出。

## Capabilities

### New Capabilities

- `win32-source-string-localization`: 定义 Win32 C/C++ 源码用户可见字符串的发现、保守术语分类、双语加载、Unicode 显示、英文回退和防遗漏验证要求。

### Modified Capabilities

无。

## Impact

- 主要影响 `src/drivers/win` 中直接产生 UI 文案的 `.cpp`/`.c`/`.h` 文件、动态字符串资源 ID 与现有 Win32 本地化辅助层。
- 更新 Win32 文案审计清单、简体中文术语表和本地化校验脚本，记录专有名词保留依据并检查保留项未被误译；不重复维护 `res.rc` 中已有菜单和对话框正文。
- 构建验证继续使用 `vc/vc14_fceux.sln`、`vc/vc14_fceux.vcxproj` 和 `PlatformToolset=v143`，不新增第三方运行时依赖。
