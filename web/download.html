Windows Quick Start (Qt GUI)

  1. Extract the entire zip file to a folder of your choice. Do not run the program from inside the zip file.
  2. Open the bin folder and run qfceux.exe. The executable is no longer in the top-level folder; the bin folder contains it together with its bundled application and Qt DLLs. You can create a desktop or Start menu shortcut to qfceux.exe for convenience.
  3. If Windows reports a missing MSVCP140.dll or VCRUNTIME140.dll, install the Microsoft Visual C++ Redistributable (x64).
  4. If no Qt configuration is found, the first launch asks where to store settings and data such as saves, save states, movies, cheats, and screenshots. Choose a per-user folder (recommended), portable storage (a config folder next to bin), or a custom folder. The choice is remembered; to change it later, run qfceux.exe --choose-config-location.

The original Windows GUI stores its settings in fceux.cfg beside its executable. The Qt GUI uses a separate configuration format and does not import those settings or move existing files. See the Qt configuration and storage documentation for details.

The top-level folder also contains palettes, luaScripts, tools, and doc folders. Keep the folder structure intact when moving the installation.

Why the Qt GUI?

The Qt GUI is where FCEUX development is focused. It includes everything the original Windows GUI offers, and it has gained a large set of features over several releases that are not available in the original Windows GUI.

  • One emulator on every platform: the same interface, tools, and configuration on Windows, macOS, Linux, and BSD.
  • Modern, customizable interface: dark mode, Qt styles and stylesheets, dockable tool windows, saved window layouts, and gamepad-operated menus for playing from the couch.
  • More ways to play: RetroAchievements, a state recorder for rewinding gameplay, a save state viewer with screenshots, a virtual Family Keyboard, and multiple gamepad binding profiles.
  • Video and recording: a choice of video drivers (OpenGL, QPainter, SDL, and Vulkan where supported), aspect ratio correction, screenshots that include scaler effects, and AVI recording through FFmpeg with modern codecs such as H.264 and H.265.
  • The complete toolset, and more: the debugger, hex editor, PPU and name table viewers, trace logger, code/data logger, RAM search, cheats, Lua scripting, movie recording, and TAS Editor are all included. Tools found only in the Qt GUI include a sprite viewer, an NES palette editor, a Lua source debugger, JavaScript scripting, a frame timing tool, an AVI RIFF tree viewer, and a performance profiler.

Original Windows GUI

The original Windows interface remains available for users who prefer its established native tools and workflow. It is also the only option for 32-bit Windows. It does not include RetroAchievements or the other Qt-only features listed above.

  • FCEUX 2.8.0 Windows 64-bit (original Windows GUI)
  • FCEUX 2.8.0 Windows 32-bit (original Windows GUI)

The fceux.chm help file is available under Help -> Help... in the emulator main menu, and an online version is also maintained.

Linux

Linux binaries are not published with releases. Install FCEUX from your distribution's package manager, or build it from source using the instructions in the README at the root of the source tree. The Qt GUI also runs on other UNIX-like systems such as BSD and Solaris.

Development Builds

Interim builds of the current in-development version are available for testing:

  • Windows 64-bit (Qt GUI)
  • macOS (Qt GUI)
  • Ubuntu Linux (Qt GUI)
  • Windows 64-bit (original Windows GUI)
  • Windows 32-bit (original Windows GUI)

Experimental network play is available in the Qt GUI. It is not available in the original Windows GUI.

Compiling

  • The Qt GUI build uses CMake 3.16 or newer.
  • The Qt GUI build requires development packages for Qt 5.15 or newer (Qt 6 supported), SDL2, minizip, zlib, and OpenGL.
  • ffmpeg libraries (libavutil, libavformat, libavcodec, libswscale, libswresample) are recommended optional dependencies that provide many encoding features for AVI recording.
  • libx264 is an optional dependency that provides H.264 video encoding for AVI recording.
  • Lua 5.1 is optional. If the system cannot provide it, an internal version of Lua is statically linked.
  • For build examples, see the workflow files in the .github/workflows directory and the scripts in the pipelines directory of the project.
  • The original Windows GUI build uses MS Visual Studio. Everything needed to compile it is included in the repository.
